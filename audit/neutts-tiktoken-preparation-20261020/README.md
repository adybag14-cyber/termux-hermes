## Native operation contract

The real public tiktoken.Encoding constructs the actual native CoreBPE with all 256 single bytes, the literal ab merge at 256, and the explicit end-of-text special token at 257. Fixed independent expectations include:

| Input | Expected tokens |
|---|---|
| Empty string | [] |
| ab ab | [256, 32, 256] |
| cab | [99, 256] |
| abab | [256, 256] |
| é🙂 | [195, 169, 240, 159, 153, 130] |
| ab + newline + ab | [256, 10, 256] |

The gate also checks literal decoding, binary single-token APIs, two-thread batch encode/decode, rejection and explicit allowance of the special token, native Regex graphemes, and local Requests/IDNA/urllib3/CharsetNormalizer behavior. Runtime connection and DNS operations are prohibited. No public encoding registry is called.

A fresh isolated environment must contain exactly the seven original distributions and satisfy all six original edges. Before/after installed-file inventories, actual mapped Tiktoken/Regex/CharsetNormalizer extensions, their direct libpython3.14.so dependencies, and original APT-owned library bodies are checked. The signed scientific foundation, compiler provenance and real Python 3.14.6 / Android AArch64 identity remain mandatory.

HOST-REVIEW.json records host checks only. A successful host review does not establish a native build or runtime pass. NeuTTS 1.4.1 retains its original >=3.10,<3.14 declaration; this independent Python-compatible dependency gate does not bypass that engine boundary.
