# Audio container platform library boundary

The full Hermes audio preparation in
[run 39083065999](https://github.com/adybag14-cyber/termux-hermes/actions/runs/39083065999)
built a fresh canonical manager and application with 101 application distributions
and 6,906 verified wheel-owned files. All 100 original wheel catalog rows remained
in the 102-row audio catalog. The owned OpenSL ES wrapper, namespace helper and
PortAudio library all loaded with their exact reviewed hashes.

The actual Sounddevice initialization result was retained:
PortAudio error -9999, “Initializing engine failed.” The container had no
Android audio framework library, Binder devices or audio services. It opened no
audio stream and accessed no microphone.

The probe then rejected the container's AOSP libc++.so. Its size and SHA-256
match the five-file platform set already independently measured in the immutable
Termux image. This is a container provenance boundary, separate from an
application library or a physical-device audio result.

## Correction

The probe now validates exactly those five shared objects. It requires the host
Docker inspection for the pinned ARM64 image, current installed aosp-libs
9.0.0-r76-4 ownership and state, canonical regular file paths, original size and
SHA-256, and ELF64 little-endian AArch64 headers. The raw Docker inspection and
both package queries are retained with each independent probe.

No image library is copied into the audio payload. The ordinary prefix library
checks stay intact. Unreviewed shared objects anywhere under opt/aosp are still
rejected, including the separately observed ICU member used by PyArrow.
A real device with no image-library mappings does not need this container-only
inspection or its package queries.

The independent review caught an initial selector that would also have included
the image linker executable. The corrected selector checks shared libraries,
matching the existing provenance scope. A mixed-mapping regression preserves
unknown-library rejection while excluding the linker. Independent replay against
all five actual APT component memory-map fixtures confirms that distinction.

## Validation

All 199 focused host tests pass, with no skips; 173 existing audio preparation
tests remain intact and 26 new cases cover the image identity, exact file bytes,
ABI, package identity/ownership, unknown paths and mixed mappings. These tests
do not load native Android libraries. The Bash driver syntax check passes.

The previous native failure is preserved in full: the 33,967,739-byte artifact,
all 84 ZIP member CRC/SHA values, 40 raw text/capture files and the exact source
head were checked. Generated bytecode stays in the verified artifact cache.
The second complete reconstruction was not reached in that failed run.

The native retry must prepare and probe two independent final paths before
complete dependency readiness is recorded. Physical permission, PCM recording,
silence-based stopping, duration limits and cleanup still need a user-started
Android device test. No release, version bump or engine admission is performed.
